# @local/wiki

原料和页面是一套，以知识库为基本单位。每个知识库绑定自己的数据源，并可在绑定上勾选要采集的库；采集和编译只处理这些绑定来源。知识库没有单独范围时，采集使用数据源上的默认库表范围；数据源也没有默认范围时，采集连接默认库的全部表。知识库里的范围不写回数据源。数据分析模式的对话框可以选择当前知识库。问数只使用这个知识库绑定的数据源，SQL 停在该知识库为数据源选择的表范围内，表和字段先从该知识库的页面和原料读取。卡片可以标成默认知识库。同一知识库里，同一来源只保留一条原料；再次采集时内容有变化就更新这一条并回到待编译，内容没变则保持原状态。数据库采集写成 `db.table` 原料。编译按 `sourceType` 选择编译器：数据库编译器把证据渲染成实体页、字典页和达到阈值的关系页。字典页是概念，关系页的类型是 relation。缺列或缺注释的正文不会发布。同一原料的决策全部落地才算完成，有一条被拒绝则该原料失败，并且不留下这一次的页面和提议。不同知识库可以各有一张同名页面。未达阈值的关系生成复核提议，写明要判断什么、为什么没有自动发布，以及接受和拒绝的结果。接受会写成关系页，拒绝不改已有页面。已经有未处理提议时不重复生成。没有编译器的来源保持 captured。采集和编译在后台运行，进度显示在标题行右侧，可以暂停和取消。原料和 Wiki 正文按 Markdown 渲染表格。

知识库页用卡片列出数据源。连通是数据源上的检测结果：读过库或采集连上过显示已连通，失败显示连接失败，否则未检测。采集是这个知识库自己的过程：本库采完显示已采集，没采过显示未采集。点开卡片编辑连接和这个知识库自己的采集范围，数据源上的默认范围保持不变；菜单里可以按已保存的范围采集，或编辑范围。设置里的数据源页用同一套卡片和向导维护连接与默认范围。新增数据源到最后一步才保存。编辑时，下一步会先保存当前这一步再前进，最后一步保存并关闭。连接参数没有变化时沿用上一次的测试结果。原料和 Wiki 可以在两种视图之间切换：目录与列表分开、正文在抽屉里，或左侧目录加列表、右侧正文。数据库原料先按数据源分目录，下面再是表、值域、连接、字典。Wiki 按页面类型分目录，关联在「关联」下，不进「概念」。

模型工具使用 `wiki_*`。`wiki_apply_decision` 要求 `evidenceRefs` 指向已经入库的原料。`wiki_collect` 在数据源插件未安装时失败。`wiki_compile` 调用已注册的编译器，不要求当前模型在线。

宿主服务名是 `localWiki`。

运行测试：`node --test test/*.test.mjs`
